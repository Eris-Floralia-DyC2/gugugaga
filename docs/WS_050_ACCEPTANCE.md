# WS 0.5.0 验收记录（2026-10-22）

## 方案及实际环境

实际在 Windows 11 x64、现有 Electron 44.9.0 工程上构建，Python 独立冻结运行时，保留 WS-Private。QQ 原生 NTQQ 数据库的一次限定只读验证显示数据库加密；检查的现成密钥提取方案需要调试断点及写进程内存，未执行。因此停止本地解密路线，只采用 QCE 6.3.2 Windows Shell 完整模式。当前官方 QQ 9.9.29-47354 的专用单版本副本已真实扫码登录，system/info 确认在线、shell、账号有效及固定版本。

## 真实数据验证

经用户明确批准，仅对现有已选微信范围内的 8 条消息，以及两个指定 QQ 群当天消息调用当前配置的 DeepSeek。未采集或上传私聊。真实测试任务先写隔离副本；微信产生 2 条具体任务及 2 条有用信息，重复分析不再生成批次；正式微信任务文件保持不变。最终冻结 worker 已复核真实总结和增量状态。

两个指定 QQ 群的元数据均可匹配，一个当日 0 条，另一个 8 条；8 条均保存原始字符串消息 ID、发送者、会话身份和毫秒转秒时间。重复自动导出后索引仍为 8 条。非空群真实 DeepSeek 总结成功，任务分析没有提取出具体任务或有用信息；空群明确为消息不足，没有发起 AI 请求或生成群确认。

非空群含 7 个 PDF 引用，当前实际关联文件不可用，7 个均在定位阶段标记失败，未伪称已读取正文。真实消息计算得到附件不完整确认；使用原任务库接口在隔离副本重复处理仍为同一条、同一 ID，手动完成后重复处理保持完成。真实 API 的错误 Token 被拒绝，恢复有效 Token 后原登录可复用。首次手机扫码通过；未强制注销账号或宣称已测试真实登录过期。

最初真实总结曾出现引文不匹配，输出被拒绝且未写入任务。现增加仅一次、相同选择范围的结构/来源纠正请求，两次仍无效则报错。未降低逐字原文和来源校验。Windows QCE 导出的长路径前缀也已根据真实输出修复，并增加路径越界保护回归。

日常 QQ 与专用 QQ 的进程可同时存在；采样专用 QQ 约 901 MiB、日常 QQ 约 432 MiB 工作集，数值随运行变化。没有把进程并存等同于长期双端登录稳定，后者及账号风控尚待持续观察。
