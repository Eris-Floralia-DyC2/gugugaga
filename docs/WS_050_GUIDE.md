# WS 0.5.0 使用及更新

## 与实际旧工程兼容

实际工程是 Electron + 独立 Python worker，默认私密目录是 WS-Private，0.4.0 已移除 ASR。本次沿用这些实际实现，保留原任务格式、桌面层、主题、窗口和多屏逻辑。没有迁移到 Tauri、改回 data/，也没有重新部署语音模型。

## QQ 首次配置

1. 在“数据源设置”添加 QQ，点击“准备 QQ 环境”，选择本机安装的官方 QQ.exe。程序仅复制一个已安装版本到当前 PrivateRoot/qq/client；原安装目录不写入插件。
2. 打开“QQ 登录”，在本机页面扫码并由本人完成手机确认。这里运行的是 QCE 6.3.2 Shell 完整模式，不是 standalone 浏览器，也不向日常 QQ 安装 Framework。
3. 点击连接或重新连接，绑定实际登录账号。到“会话总结与任务分析”刷新会话列表，按名称搜索并选择有权限访问的群或联系人。不要在 QCE 页面手动导出。
4. 保存每日时间、回看天数和执行类型并启用。WS 启动时检查 QQ；原调度到时自动导出、读取完成文件、解析附件并调用现有 AI。手动执行也会先自动采集。

以后新增微信或 QQ 指定群，只需在同一会话页面选中并保存；所有群经过同一预处理、共享附件解析、LLM、任务导入和群提醒规则，没有为首批群编写专用路径。取消选择只影响后续运行，不删除已有任务。

当前实现一天执行一次已保存规则，不是实时消息推送。临时错误保留消息和任务，五分钟后按既有调度重试；QQ 授权失效后暂停该源自动重试，重新扫码并连接后恢复。QCE 支持的历史同步不等于完整历史，长期离线、漫游、过期或未下载附件可能有缺口。

## 群消息确认

按 Asia/Shanghai 自然日，以平台、稳定账号、群 ID 和日期去重。当天没有新消息不新建；当天消息成功分析后累计没有有用信息则创建“确认xxx群的消息”。有重要通知、讨论结论或实际任务时，不生成普通无信息提醒。

图片、语音、文件、视频等任何附件未完整理解时，即使文字有用也保留同一条提醒并显示“附件未完整分析”。附件恢复且已找到有用信息后，未被手动修改的未完成提醒可自动撤销；以后再次不完整仍复用同一任务 ID。人工修改、删除、完成受到保护，已完成确认当天不重开，实际新待办仍能生成。次日有消息使用新日期；历史未完成提醒仍按原分组管理。

LLM 失败或引用无法核对不被当作“没有有用信息”；会提示错误并保留待处理状态。已知附件不完整仍可产生提醒。总结不提取具体执行任务，但同样会维护指定群的每日人工确认提醒。

## AI 服务的高级设置

展开“高级设置：消息分析提示词”，修改不超过 8000 字符的本地附加规则并单独保存。它复用 config/rules/analysis.json 的 instructions，保留排除发送者及消息类型过滤。重启保留，总结与任务分析共用；下一次新分析生效，不自动重跑历史消息。可设置重点关注课程、考试、提交截止日期等。底层来源校验、JSON 格式和隐私限制继续有效。

## 数据、安全及体积

QQ Shell 会在 PrivateRoot/qq 写入专用客户端、登录资料、Token、导出文件和资源；第三方运行环境存在账号和版本兼容风险。WS 不发送 QQ 消息，不运行密钥断点或本地解密框架。LLM API Key 继续由当前 Windows 用户的 safeStorage/DPAPI 保护；QCE/NapCat 必需的本地访问 Token 由其私密配置保存，勿分享 qq/profile 或 shell/config。

QCE 接口使用固定本机端口 40653，只允许 127.0.0.1 和 ::1 且须 Token；NapCat 登录页仅绑定 127.0.0.1:6099。QCE 自身可能监听全部地址，安全边界是验证后的本机 IP 白名单，而非宣称其只绑定回环。端口被其他环境占用时会报错，不覆盖其凭据。

发行包包含一份固定 QCE 官方压缩包，首次解压后体积约 118 MiB；还会在用户本机复制一个 QQ 版本，本次约 1018 MiB。腾讯客户端及个人登录数据不进入公开发行包。没有本地 NTQQ 解密依赖、备用采集器或 Framework 包；QCE 源码归档仅用于许可证履行，不是第二套运行环境。

## 更新与迁移

从托盘退出 WS，备份完整 PrivateRoot，替换完整公开程序目录，保留 WS-Private 或既有目录联接后启动。更新不能只换一个 EXE 而混用旧 runtime/resources。跨电脑迁移后应重新输入 API Key、重新绑定微信连接并按需重新扫码 QQ；不承诺第三方 QQ 登录状态能完整便携迁移。PrivateRoot 的 QQ 程序路径启动时重新定位，但第三方自身可能保留机器关联信息。

QQ Shell 会跨 WS 退出保留会话以供下次复用；停用 QQ 源只停止 WS 采集。需要彻底关闭时应只退出专用环境，不要批量结束日常 QQ。长期驻留的资源、断电、物理多屏热插拔和跨电脑迁移需另行验证。
