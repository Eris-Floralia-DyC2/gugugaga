# LLM API 配置与测试

本版只实现 OpenAI 风格 Chat Completions 连接测试，不会自动处理你的任务、截图和聊天记录。

1. 在提供商账户中取得你自己的 API Key 和模型名称。
2. 打开管理空间 → LLM API。
3. 填入 Base URL，例如 `https://provider.example/v1`。也接受完整 `/chat/completions` 路径，不重复追加。
4. 填 Model、Timeout（3–120秒）、Temperature（0–2）和测试输出 Token 上限（1–256）。
5. 输入 API Key，保存。留空表示保留旧密钥；清除密钥有独立按钮。显示/隐藏只切换当前输入，不会取回旧密钥。
6. 点击“测试真实推理（可能产生少量 API 费用）”。收到非空 choices[0].message.content 才显示成功。

请求为 POST，Authorization: Bearer，内容只有 `Reply with OK only.`。应用不发送待办或聊天；只显示结果类别和耗时，不显示服务端原始正文。

| 结果                 | 检查方向                                                       |
| -------------------- | -------------------------------------------------------------- |
| 配置错误             | Base URL、空模型、未保存密钥                                   |
| 密钥无效或权限不足   | 401/403，密钥、账户和模型权限                                  |
| 模型不存在           | model_not_found 等结构化错误，模型标识                         |
| 请求限流或余额不足   | 429，请求速率和账户配额                                        |
| 接口不兼容或参数错误 | 端点/协议/参数不匹配，部分模型不接受 max_tokens 或 temperature |
| 服务端错误           | 5xx，提供商服务状态                                            |
| 网络失败             | DNS、TLS、网络代理或拒绝重定向                                 |
| 超时                 | 配置超时、服务延迟和连通性                                     |

远程只允许 HTTPS；localhost/127.0.0.1/::1 可用 HTTP。Base URL 不允许用户密码、查询参数或片段。不会跟随重定向发送密钥。某些提供商返回无结构化code的404时只能分类接口不兼容，不能从不可信正文可靠识别模型问题。

密钥在 Windows 通过 DPAPI 加密，再将密文编码保存在 data/config/credential.dpapi。Base64不是加密；加密发生在 safeStorage.encryptString。密钥只由主进程解密，保存密钥不回传到 renderer、主题、日志或任务。DPAPI通常绑定当前Windows用户；同用户权限的其他程序并不被这一机制隔离，迁移电脑或账户后应重新输入。

本项目测试使用了真实本地 HTTP 服务模拟供应商和真实 DPAPI，**没有你的真实供应商密钥，不能据此宣称对某个商业服务已调用成功**。只有你填入真实配置并测试后才能确认当前服务兼容。
