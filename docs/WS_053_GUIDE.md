# WS 0.5.3 使用说明

日期折叠后，提示条高度由 22 降为 16 像素，上方间距和留白同步缩小，给待办列表更多空间。展开日期后的布局保持原样。

AI 服务的高级设置分别提供“会话总结附加提示词”“任务分析附加提示词”，每项有自己的输出 Token 上限。默认各为 4096，可填写 256–32768 的整数，实际允许范围取决于模型。设置过高、超过模型能力时会显示接口错误。这个设置控制返回长度，不会扩大采集时间或读取消息范围。连接测试的输出上限仍独立使用。

已有共用提示词会先作为两项的默认值，不会在升级时丢失。第一次保存后，两项各自生效。高级设置中还可展开只读的内置提示词及处理限制。附加要求追加到对应内置提示词之后，JSON 格式和来源原文校验继续生效。修改任务分析设置不会使未变化会话的总结缓存失效；修改总结提示词或输出上限会影响下次总结。

在会话总结与任务分析页，“最近任务分析结果”的“查看原任务库”旁新增“清空下方消息”。它清空当前待确认、重要信息和下方最近总结展示，重开页面后不恢复旧展示。它保留已创建的待办、聊天缓存、历史总结文件及增量分析记录；不会把历史消息重新标为待分析。操作进行中需等待完成后再清空。下一次执行会重新显示新的结果。

会话总结只生成工作台内的总结正文，不会把整段总结变成待办；原有必要的每日群人工确认提醒仍按既定规则处理。任务分析提取的合格待办会写入原任务库，桌面通过原同步机制自动更新，不需要额外开关。用户已取消本次逐群控制开关的需求。

总结有四个栏目：主要话题、重要通知、明确结论、待确认事项。每项需要有效来源和逐字引文；来源校验失败会针对同批消息修正一次。仍失败则明确显示失败，空栏目不会再把这种失败描述为“没有有依据的项目”。本版不宣称所有远程模型输出都能通过核对，也没有关闭来源验证。此前保存的失败结果不会因升级自动重新请求模型。

默认时间和增量机制沿用 0.5.2；日期范围按系统本地时间计算。QQ 沿用已验证的 QCE 6.3.2，登录与 Token 功能保留。

升级时保留完整 WS-Private。已生成的个人数据与干净程序包分开保存；便携包和源码包不含个人任务、聊天内容、账号登录资料或 API 密钥。
