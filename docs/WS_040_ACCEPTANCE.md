# WS 0.4.0 本轮验收报告

日期：2026-10-21。基于桌面现有 WS 0.3.1 实际修改、干净构建和打包。本报告只引用本轮回执；原任务库、桌面小组件、主题、签名、窗口和 PrivateRoot 沿用。

## 产品行为与按钮复核

日常流程现为：连接数据源和 AI 服务 → 按名称选择会话及时间 → 生成总结 / 执行任务分析 → 查看真实进度和结果。总结不创建待办；任务分析写入原 TaskRepository。两者共用采集、消息索引、PDF/文件/图片解析和 AI 服务。选择自动保存，选择本身不请求 AI。

| 原操作 | 本轮处理与实际效果 |
| --- | --- |
| 添加数据源、重新设置、重新连接 | 整理为添加及“编辑或重新连接”；保存有反馈，账号由目录/平台身份确定，普通用户不填 ID。有效凭据直接复用；迁移后的同账号目录先校验现有资料再绑定 |
| 检测连接 | 保留；检查联系人及必需的消息文件连接资料，不能仅凭联系人可读就宣称完整。失效时给出当前缺失步骤与具体原因 |
| 重新导入数据库密钥 | 日常页面移除；只在连接修复确需文件时提供“导入已有连接文件”，逐项验证所选目录数据库，不把旧电脑路径当作密钥身份 |
| 图片密钥操作 | 收到管理中的图片读取修复；没有可验证样本时明确失败，不假装修复成功 |
| 选择会话与外发范围、纳入采集开关 | 删除。v3 后端也移除旧门禁；统一以执行快照中的来源/会话/范围为目标 |
| 独立采集、采集生成任务 | 合并进会话页的总结与任务分析操作；不要求重复选择目标 |
| 启停、移除、删除历史、清除凭据、缓存清理 | 放入低频管理；逐项验证影响，删除历史先备份，均保留正式任务。缓存只清理解密数据库 |
| 语音转写、模型下载/恢复 | 前后台及运行时移除；微信、飞书语音均不下载、不转写、不生成语音确认待办 |
| MCP 开关、源勾选、群 ID、保存和 JSON 展示 | 前端移除，仅保留打开当前配置目录。后台只读 MCP 和原配置仍保留，工作台不依赖 MCP |
| QQ 入口 | 日常添加不展示尚未实现的平台；旧配置明确标记未实现，不以空实现宣称可用 |

## 本轮新执行的验证

| 分类 | 本轮证据及边界 |
| --- | --- |
| 真实原数据与 AI | 最终程序按原会话名称搜索，在原已授权 10 条消息的精确范围内重新读取微信原始数据，使用当前 DeepSeek 服务生成带来源的总结，原任务没有写入；任务分析在隔离的原任务库副本中执行，重复运行不重复新增。原 5 条任务逐项不变。正式程序恢复后，原已启用的 20:00 定时规则自动补执行，按已保存的 2 个会话及回看时间范围实际采集、调用 AI 并新增 8 条正式任务，当前合计 13 条；相关分析批次无语音消息，未删除这些新任务 |
| 构造平台端到端 | 真实 Windows/Electron、实际加密微信数据库、独立 worker 和本机 AI 协议服务；11 组流程检查通过。新会话从未单设旧采集/外发范围，选择后直接执行。验证 PDF 正文、图片解析、语音跳过、未选中会话及范围外消息排除；该 AI 服务是确定性协议夹具，不冒充真实远程模型 |
| 连接与管理 | 实际通过 UI 添加、编辑、检测、启停、同账号换目录、移除再添加；连接文件使用构造有效资料并经真实导入器验证。清除凭据、备份后删除历史、缓存清理有真实效果，正式任务保留。首次客户端内存获取使用既有实现，本轮未用新的真实账号重新扫码/获取 |
| 进度与失败 | 冻结 worker 真实事件显示检测、采集、附件、AI 等阶段，未知总量/等待模型不显示虚假百分比。实际 HTTP 401、取消、超时/重试均能结束，保留已经保存的数据。按钮防重复提交 |
| 选择与签名 | Enter 部分名称搜索、备注/昵称回退、选择立即置顶与计数、同名隔离沿用；实际重启恢复选择、签名和任务，2 组检查通过。组合输入采用本轮构造事件验证，未把 Windows 真实候选窗口逐键操作写成已通过 |
| 干净启动与便携 | 干净副本 2 组检查通过，无原身份、任务、历史或凭据；程序目录含中文与空格，启动工作目录为 System32，PATH 仅系统目录，不调用外部 Python/Conda |
| 桌面回归 | 最终程序 14 项 Windows/Chromium 检查通过，覆盖任务操作与同步、主题热更新/脚本限制、DPAPI、窗口/桌面层、混合 DPI 与负坐标、收起恢复和动画等。物理显示器拔插未新增实测 |
| 后台 MCP | 最终独立 worker 与真实授权索引隔离副本，实际初始化 4 Tools、1 Resource、1 Prompt；允许查询成功、越界拒绝。实际系统文件管理器接受当前 MCP 目录。关闭时仍有既有 closed-file stderr 诊断，不能宣称退出完全无诊断 |
| 私密迁移 | 实际导出任务/设置/历史并导入中文空格新 PrivateRoot，5 条任务逐项一致，选择/签名配置保留；凭据/profile 未导出，源停用且本机目录清空。新根实际启动通过，需重新连接而非删除任务。此为同机迁移模拟 |
| 自动及故障注入 | 19 项 Node、51 项 Python 检查通过。覆盖 v1/v2→v3、旧字段不再保存、换账号隔离、无效机器凭据保全后修复、部分连接不能冒充完整、执行快照不覆盖后来的取消选择、语音无下载、旧版待导入语音批次跳过且历史保留、来源引文校验、导入去重及迁移回滚 |

本轮实际发现并修复：进度字符编码、本机 AI 被代理转发、旧时间控件丢失秒数、运行中的总结覆盖后来选择、联系人可读但消息尚未连接等问题。失败回执和调试材料仅保留于 PrivateRoot；旧版本断言已按 v3 契约更新，未用旧报告替代新结果。

## 包体与隐私

发行目录和压缩包的精确字节、减少量及百分比见“包体积对比”。新包中无 faster-whisper、CTranslate2、ONNX Runtime、NumPy、AV、SILK、Tokenizers、Hugging Face 或模型权重。只保留 zh-CN 和 en-US 界面资源；中文和表情在实际渲染/签名中验证。

已核对并移除 4 份 WS 自管固定版本语音模型，共 1,944,852,444 字节，清理清单及哈希留在 PrivateRoot；未扫描清理无关个人文件。旧程序回滚存档可含旧依赖，但不运行、不进入新发行包。模型缓存清理与发行包缩减分别统计。

实际验证本机 API 凭据依赖 session/Local State，已与 profile 一并完整保留。泄漏检查在内存解密真实 API Key，故意泄漏的内存样本可检出，未写出明文。正式数据继续集中 PrivateRoot；原始平台目录原位只读。构建拒绝输入目录链接，不沿链接打入私密数据。实际源码、发行目录、嵌入 Python 代码和最终 ZIP 均进行泄漏检查，结果见配套摘要；个人测试、截图、日志、私密迁移包及备份均未交付到公开包。

## 未完成实测与保留边界

- 飞书旧授权需要重新登录；真实飞书导入、采集和 AI 总结未在本轮通过，不因配置入口存在而宣称通过。
- QQ 真实适配器仍未实现；没有作为可用采集功能展示。
- 没有第二台电脑。跨电脑、跨 Windows 用户、真实跨盘整根迁移、物理拔插及长时稳定性未实测；不能把同机换目录写成跨机通过。
- 真实 Windows 中文输入法候选窗口未逐键操作；组合事件保护与按名称 Enter 搜索按上述方法验证。

## 升级与回滚

桌面正式程序更新时保留原 PrivateRoot 联接，不把验收副本覆盖正式数据。配置 v2 升级前留存备份，v3 移除旧权限及语音字段，保留稳定身份、普通任务和已保存选择。具体规则见“配置迁移说明”。

回滚须先从托盘退出，恢复 PrivateRoot/development/flow-040 中的旧程序和 data-before/config/integration.json。完整保留当前任务、凭据、profile、session 和 Local State；不通过清缓存处理机器绑定凭据。语音模型不会在回滚时自动重新下载。
